# Canvas xAI Video Sharing

Jarvis can publish retained MP4 files from the Canvas Video Gallery through the
xAI Files API. The source file can have been generated by xAI, Gemini, OpenAI,
or another provider: sharing uploads the stable local copy from
`data/generated_videos/`, not the provider's temporary generation URL.

## Architecture

The browser never receives the xAI or internal Jarvis API key:

```text
Canvas Video Gallery
  -> authenticated Canvas Flask proxy
  -> authenticated internal FastAPI generated-videos route
  -> xAI Files API
```

FastAPI owns local validation, the xAI client, upload and revoke operations,
share history, and share-aware local deletion. Canvas owns only the browser UI
and protected proxy routes.

## Enable sharing

Add these settings to the mode file used by both Jarvis API and Canvas, then
restart both services:

```dotenv
XAI_API_KEY="your-xai-api-key"
CANVAS_XAI_VIDEO_SHARE=true
CANVAS_XAI_VIDEO_SHARE_DEFAULT_TTL_DAYS=7
CANVAS_XAI_VIDEO_SHARE_MAX_BYTES=48000000
```

The **Share** action appears only when the feature is enabled, `XAI_API_KEY` is
nonblank, and the retained file is an MP4 within the configured limit. Grok CLI
OAuth does not authorize the xAI Files API. Enabling this in local mode is an
explicit cloud-egress choice.

## Publish, expire, and revoke

1. Review the complete video in the Canvas Video Gallery.
2. Select **Share**, then choose 1, 7, or 30 days.
3. Confirm that the video will be public and publish it.
4. Copy or open the resulting `https://files-cdn.x.ai/...` URL.
5. Use **Revoke** in Share History to revoke the URL and delete the xAI file
   before its scheduled expiry.

Jarvis gives the xAI file the selected lifetime before creating its public URL.
The public URL inherits that file lifetime, so xAI automatically deletes the
underlying file when it expires. Expired rows remain in the local registry as
history.

The registry is stored at
`data/generated_videos/.shares/xai_video_registry.json`. It contains xAI file
and share IDs, public URLs, hashes, sizes, and lifecycle timestamps. It contains
neither API keys nor video bytes. `bin/cleanup-all` does not clean generated
videos or this registry.

Deleting a retained local video checks the registry first. When active shares
exist, Canvas offers to revoke the public URLs, delete the xAI files, and only
then delete the local video. A failed remote revoke prevents local deletion so
the public copy is not forgotten.

## Validation boundary

V1 supports only MP4 because that is the video type accepted for xAI public
URLs. Before upload, FastAPI enforces filename/path containment, rejects
symbolic links, checks the size limit, validates the MP4 with `ffprobe`, and
fingerprints the complete file. Publishing must present the same fingerprint
that Canvas reviewed, preventing an overwritten file from being published by
mistake.

Jarvis does not scan video frames, audio, captions, or container metadata for
secrets. The dialog therefore requires the user to review the complete media
and explicitly acknowledge that it will be public.
